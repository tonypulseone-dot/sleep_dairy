# Развёртывание

Мини-приложение Telegram открывается только по https, поэтому нужен домен
и сервер. Ниже — путь, который занимает минут двадцать, из них половина
это ожидание сертификата.

## Что понадобится

1. **Бот.** В Telegram напишите [@BotFather](https://t.me/BotFather) →
   `/newbot` → придумайте имя. Он вернёт токен вида `123456:AA...`.
   Запомните и имя бота без `@`.
2. **Сервер.** Любой VPS с Docker: Timeweb, Selectel, Beget. Хватит
   самого маленького — 1 ядро, 2 ГБ.
   Российский хостинг здесь не каприз: в дневнике лежат данные о здоровье
   ребёнка, а это персональные данные по 152-ФЗ.
3. **Домен.** Запись `A` должна указывать на IP сервера. Сертификат
   выпустится сам, но только после того, как домен начнёт резолвиться.

## Запуск

```bash
git clone https://github.com/tonypulseone-dot/sleep_dairy.git
cd sleep_dairy

cp .env.production.example .env
nano .env                      # заполнить домен, токен и секреты

docker compose up -d --build
docker compose logs -f bot     # убедиться, что бот поднялся
```

Секреты генерируются так:

```bash
openssl rand -hex 32
```

## Что произойдёт само

- поднимется база и накатятся миграции;
- Caddy получит сертификат Let's Encrypt для вашего домена;
- бот поставит себе кнопку меню, ведущую в приложение, — в BotFather
  ничего настраивать руками не нужно.

После этого откройте бота в Telegram и нажмите «Открыть дневник».

## Перед тем как звать живых мам

В дневнике лежат данные о здоровье ребёнка, поэтому политика
конфиденциальности — не формальность. В `.env` есть четыре поля, без
которых страница `/privacy` открывается с красным предупреждением, что
документ не заполнен:

```
LEGAL_OPERATOR=   # кто оператор данных: ФИО, ИП или ООО
LEGAL_INN=        # его ИНН
LEGAL_EMAIL=      # адрес, по которому мама пишет про свои данные
LEGAL_HOSTING=    # провайдер и город, где стоит сервер
```

Их можно поменять в любой момент: текст читает их при каждом открытии
страницы, пересобирать образ не нужно.

Вопрос, который стоит решить до запуска, — он про закон, а не про код:
**уведомление об обработке персональных данных.** Оператор данных о
здоровье подаёт его в Роскомнадзор до начала обработки. За пределы России
приложение данные не передаёт.

## Наполнение

Приложение работает и на пустой базе, но таблица режимов Виктории и
активности по возрастам загружаются отдельно:

```bash
docker compose exec app node runtime/seed-norms.cjs
docker compose exec app node runtime/seed-activities.cjs
```

Консультант заводится тем же способом — регистрация пока закрыта:

```bash
docker compose exec app node runtime/seed-consultant.cjs \
  viktoria@example.com "пароль" "Виктория" viktoria
```

Кабинет после этого доступен по адресу `https://ваш-домен/pro`.
Ссылка-приглашение для мам: `https://t.me/имя_бота?start=viktoria` — она же
показана Виктории в кабинете.

## Если с сервера не открывается Telegram

С российских серверов `api.telegram.org` доступен не всегда. Приложению он
не нужен: вход мамы проверяется подписью, которую Telegram сам кладёт в
мини-приложение. Без него не работает только бот-помощник, и его роль
берут на себя две настройки в @BotFather:

1. `/mybots` → бот → Bot Settings → Menu Button → адрес приложения,
   название «Дневник» — кнопка в чате с ботом.
2. `/newapp` → бот → название, описание, картинка 640×360, GIF `/empty`,
   адрес приложения, короткое имя `app` — прямые ссылки-приглашения
   вида `https://t.me/имя_бота/app?startapp=viktoria`.

Установщик сам распознаёт такой сервер: не включает бота, прописывает
`TELEGRAM_APP_SHORT_NAME=app` и в конце печатает эту же инструкцию. Бот
включается строкой `COMPOSE_PROFILES=bot` в `.env` — если Telegram с сервера
когда-нибудь откроется, её достаточно дописать и выполнить `docker compose up -d`.

## Перенос снов из других приложений (GigaChat)

Мамы переносят сны из прежнего трекера скриншотами или текстом из заметок.
Время со скриншотов переписывает GigaChat (Сбер): серверы в России, данные
за границу не уходят. Скриншоты удаляются сразу после распознавания, а в
дневник попадает только то, что мама проверила и подтвердила.

1. developers.sber.ru → проект GigaChat API → «Ключ авторизации» (это
   base64 от `Client ID:Client Secret`). Впишите его в `.env`:
   ```
   GIGACHAT_AUTH_KEY=ключ
   GIGACHAT_SCOPE=GIGACHAT_API_PERS
   ```
   `GIGACHAT_API_PERS` — физлицо; для ИП или компании Сбер выдаёт
   `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`.
2. `docker compose up -d --build` — образ соберётся с сертификатом Минцифры,
   без него Node не доверяет серверам Сбера.
3. Проверка доступа и сертификата:
   ```
   docker compose exec app node runtime/gigachat-check.cjs
   ```
   Проверка распознавания на настоящем скриншоте:
   ```
   docker compose cp ~/shot.png app:/tmp/shot.png
   docker compose exec app node runtime/gigachat-check.cjs /tmp/shot.png
   ```

Без ключа кнопки переноса в приложении нет. На маму — не больше 60
распознаваний в сутки, чтобы случайная «пачка» не съела лимит.

## Другие сервисы на этом же сервере

Порты 80 и 443 занимает Caddy из этого проекта. Второй сервис их не
открывает, а подключается к сети дневника, и Caddy проксирует на него свой
домен — с таким же автоматическим сертификатом.

1. В `docker-compose.yml` второго сервиса — общая сеть и никаких `ports`:

   ```yaml
   services:
     prizma:            # по этому имени Caddy найдёт сервис
       build: .
       restart: unless-stopped
   networks:
     default:
       name: sleep_dairy_default
       external: true
   ```

2. A-запись домена — на IP этого сервера.

3. Файл сайта в `/opt/caddy-sites/` (папка вне репозитория, обновления
   дневника её не трогают), например `/opt/caddy-sites/prizma.caddy`:

   ```
   prizma.example.ru {
   	encode zstd gzip
   	reverse_proxy prizma:3000
   }
   ```

4. Перечитать конфигурацию:

   ```bash
   /opt/sleep_dairy/scripts/caddy-reload.sh
   ```

   Скрипт сначала проверяет всё целиком: один файл с ошибкой ломает
   конфигурацию вместе с дневником, поэтому при ошибке Caddy остаётся на
   прежней. Незакрытую скобку Caddy показывает в следующем по алфавиту файле.

## Автообновление с GitHub

Чтобы не заходить на сервер после каждого изменения, включите один раз:

```
cd /opt/sleep_dairy && git pull && bash scripts/install-auto-update.sh
```

Дальше сервер сам раз в 2 минуты проверяет ветку `main` на GitHub. Если
там новое — подтягивает, собирает и перезапускает (миграции базы, Caddy
и занятия — тоже, когда они менялись). Сборка не удалась — продолжает
работать прежняя версия.

- Какая версия сейчас на сервере: `https://ваш-домен/api/health`
  (`version` — короткий хеш коммита).
- Журнал: `tail -f /var/log/sleep-dairy-update.log`.
- Выключить: `systemctl disable --now sleep-dairy-update.timer`.

Если на сервере руками правили файлы в папке проекта (кроме `.env`),
автообновление их не тронет и напишет об этом в журнал: `git status`
покажет, что изменено.

## Обновление

```bash
git pull
docker compose up -d --build
./scripts/caddy-reload.sh
```

Миграции накатятся сами, данные останутся на месте. Третья строка
нужна, только если менялся `Caddyfile`: он подключён файлом, и без
перезагрузки Caddy работает со старым. Если обновление меняло список
занятий, перезалейте его: `docker compose exec app node runtime/seed-activities.cjs`.

## Если что-то не так

- **Кнопка в боте ничего не открывает** — почти всегда сертификат ещё не
  выпустился. `docker compose logs caddy` покажет, в чём дело.
- **Приложение говорит «не удалось подтвердить вход»** — токен бота в
  `.env` не тот, которым открывается приложение.
